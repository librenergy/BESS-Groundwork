* **Added the Daily Performance Report template** as the second data product in `Data_Product(DP)/`, then **rebuilt it against two production reports** (an HTML issue at generator v1.10 and a PDF issue at v1.15, both from a live daily-report pipeline). The rebuild replaced the first draft's contract-limit-tracking shape with the structure real daily reports actually use — the report is organised around **availability under each contractual definition**, not around usage limits:

  - **Four availability definitions plus a combined figure** — Equipment (Installed), Equipment (Contract), Power, Operational, and **Combined = min of Contract, Power, Operational** (deliberately excluding Equipment (Installed), since installed capacity above contract capacity is not an obligation). Each gets its own row; a project adapts the names but never blends them into one "availability".
  - **Two orthogonal presentation axes**, both carried on every value: **With Excused @ 100% vs Without Excused** (excused minutes credited at contract MW, with the unexcused figure in an italic sub-line — the pair is what a dispute turns on) and **Raw vs Depth-Weighted** (shallow-SOC forgiveness on a declared curve; equipment rows carry no depth-weighted value).
  - **KPI tile row**, availability summary table, five full-day charts (including **per-PCS** availability — what turns a headline number into a work order), Energy Summary with **both RTE figures** (SOC-matched and raw, which diverge sharply on a partial-cycle day), Data Quality listing **gap-affected units by name and percentage** rather than a site-level figure that hides them, **Commercial Events** (counterparty outage reference, MW down, excused verdict, including events starting before the day and overlapping it), and a **Report Parameters** block — site/contract, setpoint tolerance bands and ramp window, depth-weighting threshold and exponent — because without it the report is an assertion rather than something reproducible.
  - New companion **`daily-performance-report-template.html`**, completed to **full markup** on a second comparison pass against the source reports (the first cut had stubbed four sections and four of the five charts as HTML comments): all 11 `h2` sections present, the complete five-row Availability Summary with the Combined row's accent emphasis and the em-dash cells where equipment rows have no depth-weighted value, all **five** chart blocks, and real Energy Summary / Data Quality / Commercial Events / Report Parameters tables. Captures the generator's actual patterns — dark `#2d3748` table headers, alternating row panels, conditional red/green value spans, the `#fff3cd` warn panel on the RTE boundary row, `colspan=2` group headers in the parameter block, and 3-per-row KPI tiles as nested tables. This is the render skeleton the generator targets — 700px centred inline-styled table layout with no CSS classes (survives email clients and headless-Chromium PDF export), KPI tile and table patterns, base64 PNG chart embedding for a self-contained archivable file, and the palette.
  - A short **"Conventions to pin down before the first issue"** checklist retains the transferable rules from the earlier draft (measurement boundary per metric, cycle definition matching the OEM guarantee, day boundary across DST, provisional-vs-final and restatement, emit from the authoritative calculations rather than recomputing) and notes that a machine-readable counterparty feed is a *separate* product, since the counterparty usually supplies the schema.

  Registered in the folder index, root index, and README Resources table. Fully genericized — no site names, codes, figures, or dates from the source reports.
